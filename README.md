# HR CRM / ATS — будівельна компанія

Корпоративна система рекрутингу: база кандидатів, вакансії, воронка, Gmail, календар, аналітика, конструктор CRM.
Архітектура: Next.js + Supabase (PostgreSQL, ЄС) + фоновий воркер. Повний проєкт — у документі «HR CRM / ATS — архітектурний проєкт».

## Локальна перевірка

Потрібен PostgreSQL 15+ з розширеннями `pg_trgm` і `unaccent`.

```bash
PGHOST=/шлях/до/сокета PGUSER=postgres ./supabase/tests/run_local.sh
```

Скрипт створює базу `hrcrm_test` з нуля, застосовує всі міграції і запускає тести. Будь-яка помилка зупиняє виконання.

## Розгортання в Supabase

1. Встановити Supabase CLI, виконати `supabase link --project-ref <id проєкту>`.
2. `supabase db push` — застосовує нові міграції.
3. Запросити першого користувача: Authentication → Users → Invite user.
4. У SQL Editor один раз виконати: `select app.bootstrap_super_admin('email@компанії');`
5. Цей користувач входить, налаштовує MFA і далі запрошує інших через адмін-панель.

## Розгортання і бекапи (GitHub Actions)

| Що | Коли | Як |
| --- | --- | --- |
| Тести міграцій | Кожен pull request і push у `main` | Автоматично |
| Staging | Після push у `main`, якщо тести пройшли | Автоматично |
| Production | Лише вручну | Actions → **database** → **Run workflow** → галочка «Розгорнути в production». Перед змінами зберігається копія схеми |
| Бекап | Щоночі о 01:17 UTC (03:17 Київ) | Автоматично: зашифрований дамп БД (age) + синхронізація файлів резюме в R2 `hr-crm-backups` |

Ключ для розшифрування бекапів зберігається лише у власника продукту (менеджер паролів + роздруківка).
Розшифрування: `age -d -i ключ.txt 2026-11-23.tar.gz.age > db.tar.gz`.

## Правила для розробки

- **Міграції лише вперед.** Застосовану міграцію не редагують — пишуть нову.
- **Кожна нова таблиця:** `enable row level security`, політики, `revoke all ... from anon`, тригер аудиту, тести в `supabase/tests`.
- **Без фізичного видалення** кандидатів, вакансій і відгуків: лише `deleted_at` (кошик). Повне стирання — окремою функцією за запитом кандидата (GDPR).
- **Секрети** (ключі Supabase, Google, AI) — лише в змінних середовища сервера, ніколи в коді чи браузері.
- Ролі `anon` і браузер не мають доступу до таблиць. API передає в БД токен користувача, тому RLS діє завжди; ключ `service_role` має лише воркер.

## Ролі за замовчуванням

| Роль | Що може |
| --- | --- |
| SUPER ADMIN | Усе, включно з ролями і конструктором (адмін-дії — лише з MFA) |
| Адміністратор | Усе, крім керування ролями |
| Рекрутер | Уся база кандидатів, відгуки, листи, співбесіди; редагує свої вакансії |
| Керівник-замовник | Лише свої вакансії та кандидати на них, без редагування |

Ролі й дозволи змінюються в конструкторі ролей без програмування.
